# collect-source 使用手册（大白话版）

> 给谁看：想收集喜欢的界面设计、但不是专业设计师的你。
> 配套：AI 用的详细规则在同目录 `SKILL.md`；本手册只讲「你说什么、看什么、点什么头」。

## 一、这是什么

一句话：**你说「录入这个网站」，AI 跑完登记、查许可、抓参数、自查、渲染样板五步，
产出一套知识库记录；你全程只在 4 个关卡出现，每次只需点头或纠错。**

你不需要懂设计术语，不需要会看色值。判断「对不对」靠两样：
机器自查表（管数字）+ 标本页对照（管感觉）。

## 二、你只需要会说的几句话

| 你说 | 会发生什么 |
|---|---|
| 「录入这个网站 https://xxx」 | 全流程启动 |
| 「这个 app / 这个界面好看，收一下」+ 在对话里贴截图 | 走截图分析（截图只在对话里看，不会存进仓库） |
| 「先只出草稿」 | 只出内容不写库，随时可续 |
| 「先停」 | 中断，进度记在本地续接文件，下次说「继续」 |
| 「按钮的颜色不像」 | AI 回查修订那条记录 |
| 「把 CASE-xxx 升为 reviewed」 | 人工转正（只有这句话能让记录转正） |
| 「查一下深色主题相关的 Case」 | 检索已有记录供你参考 |

## 三、全过程一览（5 步 4 关卡）

```text
① 定性 ──► [关卡1 范围确认] ──► ② 查许可 ──► [关卡2 许可确认]
──► ③ 抓参数(甲/乙/丙) ──► ④ 自查+渲染标本页 ──► [关卡3 草稿评审]
──► ⑤ 准备落盘 ──► [关卡4 提交确认] ──► 写库+提交+推送(再确认)
```

## 四、四个关卡你会看到什么、怎么答

**关卡 1（范围）**——AI 报：「这个站算 XX 类，打算用 XX 方式采，保存策略是 XX，对吧？」
→ 你答：**「确认」**，或纠正（比如「我只想看它的配色，别的不用」）。

**关卡 2（许可）**——AI 报：「许可查出来是 XX（依据：……），只存链接不搬东西，行吧？」
→ 你答：**「确认」**。这是替你把「会不会侵权」的判断做掉并留痕。

**关卡 3（评审）**——你拿到三样东西，只看三处：
1. **自查表**：每条观察后挂着 ✓（有据）——只要没有 ✗ 就行，数字不用你核；
2. **排除记录**：AI 列了「看到了但不建议学」的条目——看看同不同意；
3. **标本页**（`.ai/preview/` 里的一个网页文件）：浏览器打开，和原站并排摆——
   **「像不像」是你唯一要回答的专业问题**。不像就指出哪里不像。

**关卡 4（提交）**——AI 列文件清单和提交说明。
→ 你答：**「确认提交」**。推送 GitHub 会再单独问你一次。

## 五、三种采集方式（AI 自动选，你只需配合）

| 方式 | 什么时候用 | 你要做什么 |
|---|---|---|
| 甲·全自动 | 普通网站（能直接抓到样式） | 什么都不用做 |
| 乙·F12 粘贴 | AI 说「疑似 JS 渲染」时 | 按它发的指引：开网页 → F12 → 复制 `:root` 那块变量 → 粘贴进对话（约 5 分钟） |
| 丙·截图估算 | 手机 app、要登录的页面 | 把截图贴进对话；数值会标「估算」，关键值以后可复核 |

## 六、怎么判断「对不对」（非设计师版）

- **数字对不对**：不用你管。机器逐条回查原始数据，无据的会被自动删掉或降级——
  这次试运行它真抓到过一个没记录的色值并当场修掉。
- **感觉对不对**：标本页 vs 原站，并排开。颜色气质、按钮手感、字的密度——像，就过了。
- **不像怎么办**：直接说「XX 不像」，AI 回到原始数据里核对修订。

## 七、几条底线（AI 会守，但你最好知道）

1. **截图、字体、图标永不进仓库**——只存链接和自己写的文字。
2. **单个产品的观察永远标 D 级**（= 灵感参考，不是「大家都这么做」的证据）。
3. **记录永不自动转正**——candidate → reviewed 只有你亲口说。
4. 知识库不替任何项目做决定——各项目用不用，写它们自己的文档。

## 八、文件都去哪了

| 东西 | 位置 | 进仓库吗 |
|---|---|---|
| 来源登记表（总账） | `knowledge/sources.md` | 是 |
| 案例观察记录（每案例一文件） | `knowledge/cases/CASE-*.md` | 是 |
| 允许转载的文本语料 | `knowledge/corpora/` | 是 |
| 标本页（验证用网页） | `.ai/preview/` | **否**（本地看一眼就完） |
| 版本记录 | `VERSION` + `CHANGELOG.md` | 是 |

## 九、常见问题

- **录到一半不想弄了？** 说「先停」。草稿和进度在本地续接文件里，下次「继续」即可。
- **录错了想改？** 「修订 CASE-xxx 的 XX 那条」。
- **想转正？** 「把 CASE-xxx 升为 reviewed」——会单独提交留痕。
- **awesome-design-md 更新了？** 「同步 awesome-design-md」——那是另一条流程（K2）。
- **怎么找以前录的？** 直接问，比如「找和暗色主题有关的记录」。

## 十、一分钟速查卡

```text
你说「录入 xxx」
  → 关卡1 点头 → 关卡2 点头
  → 等草稿：看自查表（无 ✗）+ 排除记录 + 标本页像不像   ← 你唯一要动脑的地方
  → 关卡3 点头 → 关卡4 点头 → 推送再点一次头
完事。记录从此可被任何项目引用：CASE-xxx + SRC-xxx。
```
