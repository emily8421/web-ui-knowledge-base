## 1. 记录清单

### PAT-VIS-101｜设计令牌单点化与多主题切换

- **类型与维度**：Pattern / 视觉与布局、组件与表单行为
- **要解决的问题**：主题只有一套或颜色散落硬编码，无法低成本支持多主题（浅色 / 深色 / 品格方向），每加一套主题都要全局改样式。
- **建议**：全部颜色 / 间距 / 圆角收敛为 CSS custom properties（设计令牌），在单一文件（如 `tokens.css`）定义语义令牌（`--bg/--panel/--line/--text/--muted` + 语义色及 `-soft` 软底）；多主题 = 在容器上加 `[data-theme]` 属性切换同一组语义令牌的值；组件样式只引用令牌，不写裸色值。
- **适用条件**：纯 CSS / 无组件库或组件库支持主题变量的 Web 应用；主题数量预期 ≥2；LUMEN 类知识工作台（React + Vite + 纯 CSS）已验证形态可行（2026-08-16 试点启动，证据待试点完成后回填）。
- **不适用条件**：重度依赖第三方组件库内置主题体系的（应走组件库主题机制）；单主题营销页（无切换需求）。
- **行为契约**：不适用（纯视觉层；主题持久化与 FOUC 防闪烁属实现细节，另行记录）。
- **视觉信号**：主题差异只体现在令牌值集合；层级信号（字号 / 字重 / 间距）跨主题保持一致；语义色每主题重校对比度（正文 ≥4.5:1，WCAG AA）。
- **来源**：成熟产品观察（linear / raycast / sanity 等深色系统均呈令牌化结构，见 `cases/`）；`SRC-VIS-001`
- **证据等级**：C（多案例结构一致；待 LUMEN 试点实证后复核）
- **状态**：candidate（2026-08-16 立；待 ≥2 项目实证 + 评审后提名回流母模板）

### PAT-VIS-102｜中性底盘 + 单强调色

- **类型与维度**：Pattern / 视觉与布局（配色纪律）
- **要解决的问题**：界面用色多而杂，层级靠颜色数量堆——信息密集界面显脏，品牌色被稀释，用户无法一眼识别「什么是重点」。
- **建议**：中性色（白 / 灰 / 炭黑）承担全部结构层级（底盘、表面、正文），全场只保留一个品牌强调色并刻意压低出现频次——强调色只出现在品牌点、主 CTA 与正向状态；强调色的稀缺性本身承担层级功能。可配套：正文唯一彩色留给链接色（Slack 口径），强调色设明确使用禁区（Intercom 口径：不作装饰、不与主 CTA 同屏）。
- **适用条件**：克制型工具 / 工作台 / B 端产品的品牌用色纪律层；营销面与产品面均观察到此纪律。
- **不适用条件**：多彩本来就是品牌语言的设计；需要靠颜色区分大量类别的数据可视化密集界面（图表色板另议）。
- **行为契约**：不适用（纯视觉）。
- **视觉信号**：高频色 top 列表几乎全为中性（ima：top40 高频色几乎全中性，品牌绿仅 ×5）；强调色有明文使用禁区（Intercom：Fin 橙禁装饰、禁与炭黑 CTA 同屏）；正文唯一彩色为链接蓝（Slack）。
- **证据边界**：三案一致——`CASE-intercom-cs-workbench`（营销官网转述：炭黑 + Fin 橙）、`CASE-slack-messaging`（第三方演绎营销面：茄紫 + 链接蓝）、`CASE-ima-webui-tokens`（产品本体静态抽取：灰阶 + 品牌绿）。**证据构成为 2 案营销面（其中 1 案演绎转述）+ 1 案产品本体**，故本模式定位为「品牌用色纪律」层规律；高密度工作台界面的完整配方验证待产品本体来源补充（`CASE-ima-knowledge-base` 复核后为候选第 2 产品本体证据）。
- **来源**：`SRC-VIS-001`、`SRC-PROD-001`；`CASE-intercom-cs-workbench` / `CASE-slack-messaging` / `CASE-ima-webui-tokens`
- **证据等级**：C（多案例一致的可观察模式）
- **状态**：reviewed（2026-09-19，首批人工评审确认三案一致成立）
