# Case 观察：ima 知识库（腾讯 AI 知识管家）

- **来源**：`SRC-PROD-001`（https://ima.qq.com，链接核验 2026-08-16 可访问）
- **证据等级**：**D**（单一闭源产品观察，只作设计启发，不得表述为成熟交互经验或可用性证据）
- **状态**：candidate（2026-08-16 登记，待评审）
- **观察输入**：LUMEN 输入材料《ima前端交互设计需求说明》（v1.0，2026-07，基于 3 张界面截图整理，属需求视角的二次整理）；**未经实际产品逐屏复核**，涉及「推测」的表述保留原稿标注。
- **观察维度**：信息架构与导航、交互流程、状态反馈、人机协作

## 1. 观察到的配方

### 1.1 信息架构：极简图标 Rail + 二级列表 + 内容区

最左侧仅图标无文字的导航栏（头像 / AI 对话 / 知识库 / 笔记 / 发现 / 浏览 / 更多），中间二级列表，右侧内容区。AI 原生应用的常见范式，区别于传统菜单栏 + 工具栏。

**对知识库产品的参考点**：模块切换成本极低（知识库 ↔ AI 问答 ↔ 笔记一级平级），适合「多能力一体」产品；LUMEN 类单一知识库产品若模块数少则收益有限。

### 1.2 知识库三分区：个人 / 共享 / 订阅

二级列表按来源分组，每分组带独立「+」入口。订阅知识库可直接来自微信公众号内容源——「内容生态化」思路，区别于纯内部知识库工具。

### 1.3 AI 问答与内容浏览同屏共存（本案例核心亮点）

知识库详情页右侧**常驻悬浮问答面板**（非独立弹窗）：预置场景化推荐问题（降低提问门槛 + 暗示可答范围）+ 常驻输入框 + 可切换回答模型。浏览与提问零切换成本。

### 1.4 快速问答与任务型 Copilot 分离

左侧列表明确区分「问问ima（快速问答）」与「我的copilot（创建任务）」两个入口，对应即时问答与多步骤任务两类复杂度，避免功能混用的认知负担。

### 1.5 AI 内容一键沉淀笔记

AI 回答底部「记笔记」按钮一键录入笔记模块，与 1.3 同屏问答构成「发现 → 问答 → 沉淀」闭环；这是 ima 区别于传统笔记软件的核心差异化。

### 1.6 透明化细节

「为你保留最近 90 天历史记录」在界面直接告知数据保留策略——合规 / 存储策略的显性告知实践。

## 2. 排除记录（观察到了但不建议直接借鉴）

| 配方 | 排除理由 |
|---|---|
| 拟人化 AI 人设（lulu 昵称 + 卡通头像 + 主动询问称呼与性格） | 情感化陪伴定位；工具型知识库产品引入拟人人设增加认知噪音，LUMEN 类产品不适用 |
| 输入区功能高度聚合（Skills / 多模型切换 / @ 引用 / 多模态图标行） | 面向高级用户的高可配置性；与「降低提问门槛」的推荐问题设计存在张力，聚合度过高会抬高首次使用成本 |

## 3. 待复核标注（来自原稿的「推测」，未经证实）
